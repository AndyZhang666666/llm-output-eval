# Eval Lab · 自有任务与复核行动

日期：2026-11-01。状态：开发分支 `feat/product-depth-20261101`，本地实现，未发布。

## 这轮补上的使用路径

1. 故事/剧本作者粘贴自己的原文，复制含完整五维rubric、原有系统Prompt和返回格式的任务包。
2. 用户在自己已有的AI中运行。本站没有外部对话或服务商运行可见性，不在后台发请求。
3. 用户带回JSON，声明模型及可选运行时间、温度、是否使用原任务包。未填时间时明示使用导入时间；声明不是认证。
4. 严格检查原分、维度、均分、安全分类与元数据。失败或取消不替换当前复核材料；不自动修正异常分数，也不删除无法定位引用。
5. 原文/证据核对后，人工选择支持、存疑或待上下文。对存疑问题建立“核查评语／修改原文”处理项。完成处理只改任务状态，原始分数不变。
6. 保存本机材料并选择两份结果对照，最后导出JSON及未解决事项在前的Markdown报告。

原有历史回放、既有JSON上传和可选自配接口均保留；接口仍需用户明确点击。没有公共Key或新增服务端。评分维度、Prompt、历史18条输出及金标结果未改。

## 资料与兼容

- 旧 `version:1 / sourceText / originalResult / reviews` 报告仍可读取。新增可选 `actions / conditions / name`，不改写 `originalResult`。
- 材料身份继续为完整原文和原始结果（含元数据）规范化SHA256。处理进度、名称和人工意见不影响身份；重复导入优先保留本机复核及已保存条件声明。
- 本机库上限20份，提供名称、恢复、JSON导出和单份删除。满额时仍打开当前导入材料供复核/导出，先让人备份与删除，不自动淘汰。
- 旧最近导入槽迁移到资料库，仅在新库持久保存成功后删除旧槽。资料损坏或存储不可用时不覆盖旧存储，当前仍可操作并导出；刷新可能丢失未持久保存的新内容。
- 处理清单独立保存，最多500项。清单满时不覆盖旧项。删除资料会确认并清除其本机复核和处理项；已导出的文件不会被删除。

## 比较能说明什么

- 免Key“我的结果对照”与“历史对照”“接口运行”显式分开，不再因缺Key强制回到固定案例。
- 两侧可从资料库选择或临时导入。五维按ID对齐，分差只描述所选记录；原文、评语、引用及人工存疑同时可看。
- 同文重复记录必须原文、模型及声明条件相同；同一份记录不会重复计数。缺失条件仍明确提示，保存的重复记录不自动视为独立受控实验。
- 每侧一次是单次观察；多次显示均值及最小～最大值，沿用现有统计函数。极差不是置信区间，任何结果都不宣布赢家、显著改善或允许发布。
- 原文变化提示只取首尾公共内容之间的区域，远处多项修改会合并；不是逐句或语义diff。
