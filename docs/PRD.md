# 文本评测台 · 证据复核工作流

评审人首先要知道“哪一句值得改、理由是否成立”，随后才是分数。产品把低分、引用、原文位置和人的判断放在一起。绿色雷达只是概览，不承担发布决策。

## 已实现的任务

1. 无Key选择六个历史样本及各三次运行，查看原始模型、时间和分数。
2. 点击维度引用，用键盘也可定位。精确匹配优先，有限归一匹配明确标记；多处出现说明数量并展示第一处。未匹配不补造位置。
3. 每维记录待复核、证据支持、证据不足/评语存疑、需要上下文及最多500字备注。原始分数不变。
4. 样本、历史运行、原文和结果共同隔离复核记录；当前浏览器保存，最多500条维度记录。损坏记录拒绝读取；存储禁用时暂存本页并提示导出，不声称跨设备同步。
5. 导出原文、原始结果、人工判断与限制。历史低分CSV和本机真实运行CSV分开，历史条目可回到原文。真实运行低分记录只保留维度摘录，不承诺完整原文长期恢复。
6. 对比历史截断稿/完整稿或同文自对照。可选自己的接口独立评两稿，报告均值、极值和描述性差异，单次明确无法观察重复波动。

## 状态与恢复

- 默认历史模式不联网评分、不消耗模型额度，原文与结果绑定只读。
- 配置HTTPS接口和Key后可编辑原文。改稿清空旧结果；比较页修改文本、次数或接口都会使旧比较失效。
- 明确点击才发起N/2N请求。批次取消和90秒超时；失败不重试、不回填历史结果。没有真实服务商兼容性保证。
- 分数须是1–5整数，五维唯一且齐全；安全分类/布尔字段必须合法。证据匹配和安全标记都不是真实性或发布许可。
- Key仅在当前页面内存，刷新清除；地址和模型名可本机保存。原文只在访客明确运行时发往其选定服务商。导出不含Key。

## 设计取舍

沿用Next/React、绿色品牌和既有字体，没有迁移框架。原文与低分证据并排，人工复核在原文下；手机先给分数摘要和定位入口，再保留完整内容。方向采用achromatic-ledger（seed1130387237），保留品牌色与字体；首次工作流图方向不适合逐句核验，改为分析工作台。无装饰图片、渐变和伪业务指标。

## 仍未验证

没有真实模型重跑、新增独立标注、多人评审、云端保存、自动改稿、显著性检验或上线审批。三次历史运行只能展示本组波动；引用存在不能证明评语成立。金标报告与本轮工程验收分别记录。
